## 1. Why this project exists, and what it will produce

**The problem.** Medical-imaging AI is validated on clean, curated data and then used on scans from
other hospitals and populations, where it can fail silently. Most papers report one accuracy number
and stop.

**The thesis** (`CLAUDE.md`): a tumour segmentation model wrapped in a distribution-free error bound
and a refusal gate. The bound holds in distribution and fails under distribution shift, in
proportion to the shift. The gate cannot see cohort-level shift. We measure where it breaks, and
what a new site needs in order to restore it.

**What the finished project delivers:**

| When | Deliverable | What it shows |
|---|---|---|
| ~2026-11-24 | Semester demo + written report | DICOM in → mask → PROCEED / CAUTION / REFUSE with an honest reason. Report: `semester_report/` |
| ~Apr 2027 | MELBA journal paper | The guarantee holds in distribution. It degrades with shift (SSA → paediatric → real hospital DICOM). The gate is blind to that shift. 10–40 local labelled cases restore it, except paediatric tumour core. Gate A says whether the architecture claim survives nnU-Net; D3 says whether fine-tuning fixes paediatric tumour core |
| Summer 2027 | Capstone | An extension chosen after the GPU results (Phase 4) |

Not a product, not for clinical use. The guarantee is an average over studies, in distribution,
never per patient.

### 3.1 Next up (CPU)

**P1.4: run the OOD score.** The code is committed; the driver is not written. Next steps:

1. Delegate `scripts/ood_score.py`, the Hydra driver, with config `analysis.ood`. It extracts
   features for train/val/test (`data/preprocessed/brats` + `configs/data/splits.yaml`), SSA and
   PED. It fits on **train**, sets cuts on **val** (0.10 / 0.02 quantiles), and writes
   `outputs/ood/<cohort>_ood_score.csv` (`case_id`, `ood_score`), `thresholds.json`
   (`caution_cut`, `refuse_cut`), `model.json`, and flag rates with CIs plus a within-cohort AUROC
   for "unusable". About 0.25 s per case, ~6 min in total.
2. Error-budget primary endpoint:
   `.venv/bin/python scripts/error_budget.py model=segqc 'clinical.gatekeeper.enabled_signals=[input_qc,predicted_dice,intended_use,ood_score]' analysis.error_budget.ood_dir=outputs/ood analysis.error_budget.out_dir=outputs/error_budget_ood`.
   Compare it with the same command without `ood_score` and `ood_dir`.
3. Apply the pre-registered switch-on rule: SSA silent failure must fall by ≥ 4 of 11, **and**
   test P(accepted AND usable) may fall by ≤ 0.05. Then write the Result section and a note.

  use the memory-capped watchdog pattern (restart and resume per case). The demo uses precomputed
  jobs (`lessons.md`).
- **`outputs/clinical_jobs/`** holds the demo jobs `9c2cc294` (PROCEED) and `67b67b1d` (REFUSE).
  Do not reclaim them.
- **`intended_use` is live.** A study with no age in its header is CAUTION, not PROCEED.
- **The P1.2 anatomy caveat.** Report anatomy is read in SRI24 space, and our registration
  disagrees with BraTS's by a median ~6 mm (note 55).
- **Gate A is the credibility gate.** Until it reports, every C1 sentence ends with "not yet tested
  against nnU-Net".
